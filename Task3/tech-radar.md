# Технический радар

Первые шесть строк это текущий стек, дальше идут предлагаемые изменения и инструменты к ним. Кольцо радара указано там, где оно не adopt.

| Технология | Бизнес-сценарии |
| --- | --- |
| Go, Java, Python | На Go и Java написаны финтех-сервисы, на Python ИИ-сервисы и DAG'и Airflow |
| Power BI | Остаётся конструктором отчётов для портала самообслуживания, но теперь строит их по витринам доменов через Dremio |
| PowerBuilder | Используют операторы клиник |
| MS SQL Server 2008 | Используется DWH, а он продолжает использоваться в домене клиник |
| ESB Apache Camel | Используется в существующующих интеграциях между клиниками, ИИ и финтехом |
| Yandex Cloud | Переезд в облака используется для улучшения масшабируемости для новых интеграций и бизнес-направлений |
| Terraform | Используется для автоматизации развертывания. Улучшает вопспроизводимость, надежность, в потенциале экономит ресурсы |
| Data Lakehouse на Object Storage, Iceberg и Nessie | Дает быструю отчётность на сотнях терабайт, витрины всех доменов лежат в одном открытом формате |
| Apache Airflow | Витрины считаются заранее по расписанию, а не в момент запроса |
| Dremio | Power BI получает единый SQL-доступ ко всем витринам |
| DataHub | Сотрудник сам находит витрину и её владельца, новый домен регистрирует свои продукты данных |
| Keycloak | Сотрудник входит в портал один раз через SSO, а уровень доступа к витринам определяется его ролью |
| Managed PostgreSQL | БД финтеха |
| Yandex Data Transfer -> trial | Для переезда данных из локального DWH в облако |
| Data Mesh -> trial | Домен владеет своими данными как продуктом, а платформа общая, поэтому направления развиваются независимо |
