# Разделение на домены

Делим систему по подразделениям из описания компании, так как у каждого из них свой бизнес-контекст, своя команда и свой регулятор.

| Домен | Что в него входит | Какие бизнес-сценарии поддерживает |
| --- | --- | --- |
| Клиники | Интерфейс оператора на PowerBuilder и DWH на MS SQL Server с приёмами, медкартами, историями болезни, результатами исследований, счетами за услуги, персоналом и инвентарём клиник. Продукт данных выгружает в Lakehouse только операционные таблицы, медкарты и исследования остаются внутри домена | Работа операторов и врачей в клиниках. Результаты исследований уходят в ИИ на анализ по существующему маршруту ESB, заключение возвращается в карту пациента. В витрине домен даёт отчёты по приёмам, услугам, счетам, персоналу и инвентарю |
| Финтех | Финтех-сервисы на Go и Java и своя БД на PostgreSQL с банковскими счетами, кредитами и финансовой историей клиентов. Логика финтеха из DWH переезжает в сервисы домена | Банковские продукты и запуск новых финтех-сервисов. Новый сервис разворачивается в среде домена, берёт счета клиник по существующему маршруту ESB, пишет в БД финтеха и попадает в витрину через продукт данных, DWH при этом не трогаем |
| ИИ-сервисы | ИИ-сервисы на Python и хранилище моделей и датасетов на Object Storage. Логика под ИИ из DWH переезжает в сами сервисы | Анализ результатов исследований, диагностика и назначения. Медданные приходят из DWH клиник через ESB, заключение возвращается обратно, обучающие выборки остаются в домене. В витрину домен отдаёт только метрики моделей |
| Головной офис | Внутренние сервисы управления сетью клиник, финансы и отчётность группы | Целостная картина по группе. Продукт данных головного офиса читает витрины остальных доменов из Lakehouse и публикует сводную аналитику |
| Новые направления, фармацевтика и электроника | Операционные системы партнёра на его стеке и продукт данных направления по общему контракту платформы | Подключение нового бизнеса. Партнёр получает свою среду, публикует витрины в свою зону Lakehouse, и они сразу видны в портале |
| Платформа данных самообслуживания, общая для всех доменов | Lakehouse на Object Storage и Iceberg с каталогом Nessie, Airflow, Dremio, DataHub, Power BI и SSO на Keycloak. Платформой владеет отдельная команда, данные в ней принадлежат доменам | Витрина данных. Сотрудник находит данные в каталоге, Dremio отдаёт витрины по правам роли, Power BI собирает отчёт по любым срезам |

## Логика разделения следующая

Границу домена проводим по подразделению, потому что у каждого свой контекст и свои регуляторные требования. Данные принадлежат тому домену, где они рождаются, поэтому медкарты остаются в клиниках, банковские счета в финтехе, а сводная аналитика у головного офиса. Каждый домен получает свою изолированную облачную среду, но один общий контракт с остальными - продукт данных, который публикует витрины в свою зону Lakehouse. Логика финтеха и ИИ из DWH переезжает в их домены, в DWH остаются только данные клиник. Новые направления подключаются по тому же шаблону через Lakehouse.

Для бизнеса это даёт ускорение вывода продуктов, так как команда домена меняет только свои сервисы и не ждёт доработки DWH. Направления развиваются отдельно, при этом целостная картина сохраняется, так как витрины всех доменов лежат в одном Lakehouse и головной офис собирает из них сводную аналитику.
