# Проблемные места

| # | Проблема | В чём выражается | Какие бизнес-сценарии страдают |
| --- | --- | --- | --- |
| 1 | Бизнес-логика живёт в DWH | Любое изменение в финтехе или ИИ - это доработка DWH | Независимое развитие финтеха и ИИ, запуск новых направлений, time-to-market в целом |
| 2 | Отчёты строятся часами | Сотни ТБ в одном MS SQL, под каждый сценарий использования свои трансформации, и всё это считается внутри DWH | Управленческие решения принимаются с задержкой, целостной картины по ключевым показателям в моменте нет |
| 3 | DWH используется аналитикой и обслуживает клиники | Интерфейс оператора пишет прямо в DWH, туда же ходит BI. Тяжёлые отчёты и работа клиник конкурируют за одну базу | UX операторов в клиниках страдает пока считаются отчёты, и наоборот |
| 4 | Нет возможности самообслуживания | Любой новый срез - это доработка в коде | Сотрудник не может получить отчёт по любому срезу, витрина не масштабируется на новые направления |
| 5 | Легаси-стек: MS SQL Server 2008 и PowerBuilder | Поддержка вендора для SQL Server 2008 закончилась ещё в 2019 | Требования регуляторов по мед- и финданным (ИБ), стоимость поддержки, риск для доступности клиник |
| 6 | ESB как единственная точка интеграции | Шина является единой точкой отказа и хранит в себе логику всех интеграций | Подключение новых финтех-сервисов и партнёров, под риском находится доступность всех интеграций сразу |
| 7 | Медицинские и финансовые данные лежат в одной базе без разделения по доменам | Уровни доступа приходится реализовывать внутри одного DWH | Сложно ограничивать доступ, риск нарушения требований регуляторов |
| 8 | Инфраструктура on-premise, нет отказоустойчивости | Трудность масштабирования, сложность поддержки | Страдает доступность критичных сервисов, сложно масштабировать ресурсы под рост данных и под новые бизнесы |
