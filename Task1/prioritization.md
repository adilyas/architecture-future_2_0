# Приоритизация проблем

Используем метод MoSCoW, так как у бизнеса есть чёткие цели на год и надо оценить приоритет задач для их достижения. Матрица Эйхенхауера больше про срочность. Она так же могла бы использоваться, но MoSCoW в данном случае достаточен.

| Приоритет | Проблема | Почему |
| --- | --- | --- |
| Must | 1. Бизнес-логика живёт в DWH | Необходимо для независимого развития финтеха и ИИ, а также для масштабируемого подключения новых направлений. Кроме того, это лавный ограничитель time-to-market |
| Must | 2. Отчёты строятся часами + 4. Нет возможности самообслуживания | Витрина данных с возможностью самообслуживания является одной из основных целей бизнеса. Кроме того, данная проблема напрямую влияет на скорость принятия управленческих решений |
| Must | 7. Медицинские и финансовые данные лежат в одной базе без разделения по доменам | Без разделения данных по доменам и доступа по ролям витрину вообще нельзя открывать сотрудникам. Это противоречит требованиям регуляторов |
| Should | 8. Инфраструктура on-premise, нет отказоустойчивости | Критичным системам нужны бэкапы и геораспределение. Запуск витрины это не блокирует, но бизнес уже планирует переезд в облако |
| Should | 5. MS SQL Server 2008 | Так же привязано к переезду в облако. Отсутствие поддержки(и патчей безопасности) нарушает требования регулятора |
| Should | 3. DWH используется аналитикой и обслуживает клиники | Решается само по себе в процессе решения проблемы #1 |
| Could | 6. ESB как единственная точка интеграции | Новые интеграции через шину не заводим, старые оставляем. Полная замена за год не нужна |
| Won't | 5. PowerBuilder | Замена интерфейса оператора создает риск для клиник и не дает никакой ценности в рамках целей этого года |
